# Public traffic-data downloads

31 October 2026 · Public page: `/data/`. Linked from C2C → Tools & reference → Public traffic data. A domain was discussed but no exact hostname was supplied; the page uses the existing public PASADA Site. No custom DNS or government-domain connection has been configured.

## Implemented interface

Visitors select one or more of the three published study intersections and a start/end date and time in Asia/Manila (UTC+8). Time ranges are half-open `[start, end)`, minute-aligned and limited to 31 days per query. Choose 1, 5, 15 or 60 minute lane aggregates, preview paginated records, and download CSV or JSON. JSON carries query/release metadata; metadata and a data dictionary can also be downloaded separately. Editing filters disables old downloads until Preview runs again.

The static archive is `dist/data/archive.json`, schema `pasada.public-traffic/0.1.0`. Its bundled release is **synthetic**, uncalibrated, generated by `node tools/build_public_archive.mjs` from the existing balanced deterministic engine. The calendar anchor **30 October 2026, 08:00–09:00 Philippine time** is assigned solely to exercise date-range selection. It is not historical Mandaue traffic. There are 54 counting lanes and 3,240 lane-minute records. The area-planner's 118 mapped signalized candidates do not become data archives merely because their geometry is available.

## Count and quality rules

- One 60 m upstream entry detector per incoming lane; one downstream exit counter per outgoing lane. Never sum 5 / 30 / 60 m detections as separate vehicles.
- Store interval deltas of cumulative counters only after checking boot/session, sequence, ordering and reset continuity. The sample generator throws on a negative/noninteger delta. A real ingest adapter with these event gates is still pending.
- Zero is a valid observed count. Missing, invalid and reset intervals are unavailable. Do not interpolate or manufacture zeros. Duplicate lane/time keys fail the query.
- Aggregate counts are published only when every source minute is complete. Partial groups have `vehicle_count: null`, observed/expected seconds and incomplete quality. Completely missing groups have no row; query metadata reports the missing lane-seconds, including requests outside archive coverage.
- Incoming/outgoing summaries count complete groups only. Cross-intersection sums are passages, not distinct vehicles. No travel-time, speed, occupancy, turn classification or calibrated queue metric is inferred from these aggregate counts.
- Public records use an explicit field allowlist. Project configuration, fleet registrations, emergency trajectories, hardware identities, credentials and raw CCTV are not loaded by the public page. CSV text values are quoted and spreadsheet-formula prefixes escaped.

## Remaining integration

This version is a functional public **demonstration download interface**, not a continuous archive service. A real data pipeline needs coordinator packet ingestion, durable indexed storage, synchronized event/receive time, idempotency and reset/gap handling, reviewed intersection/lane catalog revisions, retention and release rules, agency-approved publication, and release provenance. There is no field upload, public SQL interface or arbitrary database query feature here.

Recommended chain: coordinator → authenticated C2C ingest → private append-only event store → validated lane/time aggregates → approved public release/API → this read-only explorer. Keep traffic control local per intersection. Public queries read an archive and never control signals or compete with signal timing tasks. A later C2C override API is a separate authorized control interface.

Use CSV for students/spreadsheets and JSON for scripts. SQL belongs behind a bounded API, not in the public browser. A future API contract can use `intersection_ids`, `start_utc`, `end_utc`, `aggregation_minutes`, `format`, pagination and a release ID; it must enforce limits server-side. The static client restrictions in this prototype are not server authorization or resource limits.

## AI Scratchpad completion convention

The existing **Done / verified** checkbox in column F is retained; a second status column is not created. Read the checkbox, original Status / basis and latest related row before repeating work. Checked applies only to the stated verified scope in C/E. Partial, pending and hardware-unverified deliverables stay unchecked, with a separate completed row for a finished subset. Reference rows are context, not automatic tasks; superseded records point to later evidence. Re-read live cells before updating, preserve other authors' rows, and verify after writing. For claimed work, record owner, UTC time and bounded scope in a new row/note. This convention reduces duplicate work but is not an atomic multi-bot lock.

## Verification

`tests/public-data.test.mjs` checks timezone conversion, calendar validity, half-open filtering, selected sites, aggregation/count conservation, missing data versus zero, partial coverage, invalid counts, duplicate records, query limits, allowlisted exports and CSV escaping. Browser QA separately covers form changes, empty results, downloads and layout. Field acquisition, actual UTC synchronization and a calibrated SUMO archive are outside this evidence.
